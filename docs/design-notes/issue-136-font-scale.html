Design note · ha-teamtracker-scoreboard-card

A card-level font_scale multiplier over the type set

Issue #136 Slug font-scale Status approved Type feature Slices 1

Problem

#132 and #133 made the card's layout dimensions configurable — team_width, logo_width, score_width, colon_width, row_height — each a --scoreboard-* custom property with a px fallback, emitted onto <ha-card> through a cssVars table in _render. The type sizes were left behind: every font-size in src/styles.ts is a hardcoded px literal.

RuleSizeRuleSize
ha-card (base)14px.score20px
.section-header15px.colon17px
.team-name13px.message13px
.team-rank9px.msg-sub10px
.team-pos11px.tv-badge8px
.empty13px.tv-tooltip::after10px

This is a readability gap, not a layout one: a viewer who wants the whole card a notch larger (or smaller, on a dense dashboard) has no knob. #133's dimension options address “make the row fit”; they do not touch text size. Hence a separate issue, and — per the issue — a separate decision on shape (one multiplier vs per-role knobs), taken below.

Prior art

LESSONS.md has no entry for a typography or font-size problem class — none has been fixed and guarded. Two existing entries constrain how this is wired, both from #132/#133:

  • Test on the style attribute, not innerHTML. CARD_STYLES is inlined into the shadow DOM, so any var(--x, fallback) is always in shadowRoot.innerHTML. A --scoreboard-* option is asserted on shadowRoot.querySelector("ha-card").getAttribute("style"), paired with a CARD_STYLES-contains check for the stylesheet side.
  • The cssVars table is serialised through .filter(([, v]) => v). A value that must survive has to be truthy; a value that must be dropped in the default case can rely on that filter, but a “looks-like-a-default” value (here, font_scale: 1) needs an explicit guard, not the truthy filter, so intent is unambiguous.

The reusable pattern is #133's cssVars table itself: add one entry, add one var() reference in styles.ts, add one type field, test both sides.

Decision from the grill

Shape A single card-level font_scale (number, default 1) that multiplies every type size by the same factor. Not per-role knobs.
  • One multiplier, not per-role. The issue frames this as readability (“scale the text”); the px scale in styles.ts was hand-tuned as a set (score ≈ 1.5× team-name, rank ≈ 0.7×). A uniform factor preserves those ratios; per-role knobs (6–9 new options, README rows, type fields, tests) force the viewer to re-balance the scale themselves for the common “just make it bigger” want. Per-role stays a possible follow-up (see Adjacent opportunities) and the chosen mechanism leaves room for it.
  • Scales the whole stylesheet. All twelve text rules above — the nine content rules plus .empty (“no games found”), .tv-tooltip::after, and the ha-card base size that loose inline spans inherit. Excluded: .tv { font-size: 0 } (an inline-whitespace-collapse trick, not type — calc(0px × s) is still 0, but leaving it literal is clearer) and the two inline styles in index.ts (#sc-version badge, debug overlay) — dev/chrome affordances that should not move with viewer config.
  • Card-level only, not per-section. Matches #133's dimension knobs (all card-level; per-section options are behavioural — season_mode, score_blink, show_position). Per-section would need the variable emitted on each section wrapper — sectionHtml sets no inline layout style today — for a mixed-density use case nobody has asked for.
  • Emit only when set and not 1; no validation. font_scale != null && font_scale !== 1 ⇒ String(font_scale), else undefined. No clamp, no range check — consistent with #133, which passes CSS values straight through. 0 / negative / garbage simply fail the calc() and fall back to 1. Documented as “a positive multiplier; 1 is the baseline”.

How a value maps to sizes

Each rule keeps its px literal as the baseline and multiplies by the variable, which defaults to 1 when unset. Rendered size is baseline × font_scale; CSS does the arithmetic, no JS math, no unit handling.

RoleBaseline1 (default)1.151.50.85

.section-header15px15px17.25px22.5px12.75px

.tv-badge8px8px9.2px12px6.8px

Every role moves by the same factor, so .score stays ≈1.5× .team-name at any scale. Fractional px is fine; the browser rounds at paint.

Design it twice

Chosen

A · calc() per rule + one CSS var

Rewrite each font-size: Npx as font-size: calc(Npx * var(--scoreboard-font-scale, 1)). _render adds one cssVars entry. 

.team-name {
  font-size: calc(13px * var(--scoreboard-font-scale, 1));
  /* … unchanged … */
}
  • Baseline px numbers stay in styles.ts, where the type scale is read and tuned — nothing moves into a TS table.
  • One variable, not twelve. The .filter(([, v]) => v) keeps it out of the style string in the default case.
  • Slots into the exact #133 pattern: one cssVars line, N var() references, one type field, two-sided test.
  • Future per-role knobs nest inside the same calc: calc(var(--scoreboard-team-name-size, 13px) * var(--scoreboard-font-scale, 1)) — no rework.
  • Trade-off: calc() is a new idiom in styles.ts (#133's dimension rules are bare var()); twelve rules gain noise. Multiplication genuinely needs it.
Rejected

B · em units off a scaled ha-card base

Set ha-card { font-size: calc(14px * var(--scoreboard-font-scale, 1)) } and convert every child font-size from px to em (.score 20px → 1.429em, …). One calc, scaling is then free.

  • Compounding bug. .msg-sub is a DOM child of .message (see messageHtml): em resolves against the parent's already-scaled size, so .msg-sub scales by the factor twice. Every nested-text case is a latent double-scale.
  • rem can't rescue it: inside a shadow DOM rem refers to the document root, which the card doesn't control and which drifts with the HA page theme.
  • Mechanical churn: twelve px literals become fractional em (0.929em reads worse than 13px), every one a regression surface.
  • All to save eleven * var() fragments. Not worth a correctness trap.

A third option — _render computes each scaled px in JS and emits twelve --scoreboard-*-size vars, styles.ts using bare var(--scoreboard-score-size, 20px) as #133 does — was set aside: it moves the type-scale baseline out of CSS into a TS table (two places to look) and emits twelve vars for zero gain unless per-role knobs actually ship. If they ever do, option A extends to cover it anyway.

The change — one slice

  • src/types.ts — font_scale?: number on CardConfig, with a one-line intent comment (“uniform multiplier over every font-size; 1 = baseline”).
  • src/index.ts — destructure font_scale in _render; add to the cssVars table "--scoreboard-font-scale": font_scale != null && font_scale !== 1 ? String(font_scale) : undefined. Explicit guard — not leaning on the truthy filter — per the LESSONS.md note.
  • src/styles.ts — wrap the twelve text font-size literals in calc(…px * var(--scoreboard-font-scale, 1)). Leave .tv { font-size: 0 } literal.
  • test/index.test.ts — describe("font_scale"): 1.15 emits --scoreboard-font-scale:1.15 on the <ha-card> style attribute; omitted and 1 emit nothing.
  • test/snapshot.test.ts — CARD_STYLES contains a representative calc(20px * var(--scoreboard-font-scale, 1)) (the .score rule); snapshot refreshed.
  • README.md — font_scale row in the Options table; a short paragraph near Layout dimensions: uniform multiplier, 1 baseline, ratios preserved, and the interaction note — a large font_scale against a fixed row_height can clip ascenders/descenders, so raise row_height alongside it.

No render.ts touched. No getCardSize() change — it keys off row_height, which the viewer sets explicitly; font_scale deliberately does not nudge it (knobs stay independent, as in #133). Coverage stays at 100%.

Design invariant touched

None. The CLAUDE.md invariants cover sort mode, logo URLs and the position cell; an additive type-scale multiplier touches none of them. The option is documented in README.md only, alongside the #133 dimension knobs.

Adjacent opportunities

  • Per-role type knobs (score_size, team_name_size, …) — this change makes them cheap: nest var(--scoreboard-<role>-size, Npx) inside the calc already in place. File separately only if a viewer actually asks; not folded in here.
  • A line-height / density scale — separate concern (vertical rhythm, not glyph size); not pursued.
  • Move #sc-version / debug-overlay font sizes into styles.ts for consistency — unrelated cleanup, out of scope.
  • Config validation for numeric / boolean options — still absent card-wide, still out of scope.

This change makes per-role knobs trivial (same calc) and forecloses nothing.

Slice log

Slice 1 — accepted. The whole change, as designed — no deviation from the note.

  • src/types.ts — font_scale?: number on CardConfig with the intent comment “uniform multiplier over every font-size; 1 = baseline”.
  • src/index.ts — _render() destructures font_scale and adds one cssVars entry: "--scoreboard-font-scale": font_scale != null && font_scale !== 1 ? String(font_scale) : undefined. The explicit != null && !== 1 (not a truthy check) keeps the 1 no-op out of the style string and lets 0 through as --scoreboard-font-scale:0 — a valid calc() operand, intentional GIGO, no validation (consistent with the width knobs).
  • src/styles.ts — the twelve text font-size: Npx literals become calc(Npx * var(--scoreboard-font-scale, 1)). .tv { font-size: 0 } left literal (inline-whitespace-collapse hack, not type; its visible child .tv-badge re-sets a scaled size).
