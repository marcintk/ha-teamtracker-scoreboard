Background

Every row the card draws is a fixed flexbox: a narrow position cell, a team-name column, a logo, a score, a colon, the mirror of score/logo/name for the opponent, then a flexible message column. Until recently every one of those widths and the row height was a bare number in src/styles.ts — .logo was 30px, .score 34px, .colon 9px, and the row and its cells were all 28px tall.

#132 made one of these — the team-name column width — adjustable, and set the pattern the rest would follow: a config option becomes a --scoreboard-* CSS custom property written onto the <ha-card> element, and the stylesheet reads it with the old constant as the var() fallback. Set nothing and the fallback wins, so the card is byte-for-byte what it was.

This change finishes the job. Four more symmetric knobs — logo_width, score_width, colon_width, row_height — plus team_width, which replaces team_col_width and additionally accepts a [left, right] pair so the two name columns can differ. getCardSize(), the height hint Home Assistant uses to place the card in a masonry layout, learns to read row_height.

The idea

One table instead of a growing string

_render() used to bolt each custom property onto the <ha-card> style with its own ternary fragment: ${team_col_width ? `--scoreboard-team-col-width:${team_col_width};` : ""}. One is fine; seven is an unreadable ~200-character line where a mistyped property name or a missing semicolon fails silently. So the emission becomes a small table:

const cssVars = {
  "--scoreboard-team-col-a-width": teamAW,
  "--scoreboard-team-col-b-width": teamBW,
  "--scoreboard-logo-width":  logo_width,
  "--scoreboard-score-width": score_width,
  "--scoreboard-colon-width": colon_width,
  "--scoreboard-row-height":  row_height,
};
const varStr = Object.entries(cssVars)
  .filter(([, v]) => v)          // drop unset (and "")
  .map(([k, v]) => `${k}:${v};`)
  .join("");

Adding a knob — a font scale, say — is now one line in one place.

row_height moves everything vertical together

The row, the logo cell, the score cell, the colon cell and the logo <img> all read var(--scoreboard-row-height, 28px) for their height. Set row_height: 40px and the whole row grows as a unit — a taller strip with a taller logo — rather than 28-pixel cells stranded inside a 40-pixel row.

team_width: one value, or two

team_width is either a length or a [A, B] pair. _render() flattens the distinction before it ever reaches the table:

const tw = team_width ?? team_col_width;         // fall back to the old option
const [teamAW, teamBW] = Array.isArray(tw) ? tw : [tw, tw];

Then .team-col-a and .team-col-b each resolve through a two-step fallback: var(--scoreboard-team-col-a-width, var(--scoreboard-team-col-width, 99px)). A caller who only ever set team_col_width lands on the middle rung and gets exactly the old behaviour; the shared .team-col width rule is gone.

The cost of asymmetry The score and colon sit centred between two equal columns. Give the columns different widths and the centre line moves — team_width: [150px, 70px] pushes the colon left. That is the documented trade-off of the pair form, not a layout bug.

getCardSize follows row_height

The masonry hint was ceil(rows × 28 / 50). It now parses row_height the same way the code already parses height — parseInt, and fall back to 28 if it is not a plain pixel value — so a card of 40-pixel rows reports a proportionally taller estimate.

The code

Three production files.

src/types.ts

CardConfig gains logo_width?, score_width?, colon_width?, row_height? (all ?: string) and team_width?: string | [string, string]. team_col_width stays, tagged /** @deprecated use `team_width` */.

src/index.ts

_render() destructures the new options, resolves tw = team_width ?? team_col_width and normalises it to [teamAW, teamBW], then builds the cssVars record and joins the set entries into the string appended to haCardStyle (after the existing height and position:relative fragments). getCardSize()'s section-based branch swaps its hardcoded 28 for parseInt(row_height) when that is finite.

src/styles.ts

CARD_STYLES swaps the literals for var(…, <constant>) on .game-row height, the .logo / .logo img / .score / .colon width and height. The .logo img width fallback stays 28px (its old value, not the .logo box's 30px) so an unconfigured logo does not grow. The shared .team-col width / min-width rules are deleted; .team-col-a and .team-col-b get their own width / min-width with the nested team-col-a-width → team-col-width → 99px fallback.

Guardrail tests

test/index.test.ts › "layout dimension options" (each option emits / omits its property on the <ha-card> style attribute — per the LESSONS.md rule, not innerHTML), "team_width" (scalar sets both, pair sets each side, team_width beats team_col_width, neither set emits nothing), and two getCardSize cases ("40px" scales, "auto" falls back to 28). test/snapshot.test.ts › "CARD_STYLES" gains the six var() wiring assertions and drops the stale shared-.team-col one; the CARD_STYLES snapshot is refreshed. Coverage holds at 100%.
