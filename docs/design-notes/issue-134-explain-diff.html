Background

When the standings-position column landed, it made a deliberate choice: the 18px .team-pos cell is rendered as the first child of every row — carrying the rank in a standings sort, blank under by-date or when a section sets show_position: false. Always drawing it means a card that stacks a league table above a fixture list keeps every row's left edge in the same place, and no code has to look across sections to decide.

The bill for that falls on one kind of card: one whose sections are all fixtures. It carries an empty 18px gutter it never had before, buying an alignment guarantee it has no use for, with no way to decline.

The layout-dimension work that followed gave the card a tidy mechanism for exactly this: a cssVars table in _render() whose entries become --scoreboard-* custom properties on the <ha-card> element, each read by the stylesheet with a var() fallback. This change is one more entry in that table.

The idea

A card-level show_position: false sets one property:

// _render(), inside the cssVars table
"--scoreboard-position-display": show_position === false ? "none" : undefined,

and the stylesheet consumes it:

.team-pos { display: var(--scoreboard-position-display, block); /* … */ }

Why === false and not !show_position

The table is serialised through .filter(([, v]) => v) — only truthy values become declarations. So undefined (the option omitted, or set to true) is dropped for free, and nothing is emitted. A loose !show_position would be wrong twice over: it is redundant with the filter for the undefined case, and it would also fire on 0 or "". Only an explicit false should act, so the check is explicit.

Why display: none

.team-pos is a flex child of .game-row with width: 18px; min-width: 18px. display: none takes it out of the flex formatting context entirely — the track it occupied is gone, not merely emptied — so the row is byte-for-byte the pre-position-column layout. visibility: hidden or width: 0 would leave a seam.

Two switches, one name show_position exists on both the card and a section, and they are not the same lever. The section option blanks the number but keeps the cell, so sibling sections stay aligned. The card option removes the cell. They are read from different objects (this._config vs the section), never crossed, and the card-level one wins outright — if it is false there is no cell for a section's number to live in.
Card show_positionEffect
omittedgutter present on every row (unchanged)
trueidentical to omitted — a safe no-op
false--scoreboard-position-display: none → no gutter anywhere

The code

Five lines across three files; src/render.ts is untouched.

src/types.ts

show_position?: boolean added to CardConfig (the field already exists, independently, on SectionConfig).

src/index.ts

_render() destructures the card-level show_position and adds one entry to the cssVars table: "--scoreboard-position-display": show_position === false ? "none" : undefined. The existing filter/join does the rest.

src/styles.ts

.team-pos gains display: var(--scoreboard-position-display, block) as its first declaration. The <div class="team-pos"> that rowHtml emits is unchanged — when the card opts out it is simply an inert, zero-area node.

Guardrail tests

test/index.test.ts › "card-level show_position": false emits --scoreboard-position-display:none on the <ha-card> style attribute; omitted and true emit nothing. test/snapshot.test.ts › "CARD_STYLES" pins the display: var(…) wiring; the CARD_STYLES snapshot gains one line. Coverage stays at 100%.
