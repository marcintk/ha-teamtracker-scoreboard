Background

A card with several sections stacks them: _render() maps every section through sectionHtml and drops the whole array into one child slot of the <ha-card> template. Fine on a laptop; cramped on a wall tablet, where you would rather watch one league for a minute and then move on.

Two things made this more than a rendering tweak. First, the card had no interactive parts — no <button>, no @click, no event listener anywhere in src/. Second, everything it drew was a pure function of hass: given the same Home Assistant state, the same pixels. A carousel breaks both assumptions. It needs a control the user can press, and it needs to remember two things that are nobody's business but the card's: which section is showing, and whether the user has paused. It also needs a timer, joining the three the card already runs (_fixedTimer, _renderTimer, _blinkTimer).

The card is a bare HTMLElement with a hand-rolled lit render() — no LitElement, no reactive properties. So a field like _slideIndex changing does nothing on its own; something has to call _render().

The idea

One new card option, slide_sec (a number, seconds). The carousel is on when slide_sec > 0 and there are at least two sections; otherwise the card stacks exactly as before — unset, zero, or a single section all mean “no change”.

When it is on, _render() emits only sections[_slideIndex] instead of the whole array. A timer bumps the index (modulo the section count, so it wraps) and re-renders. The swap is a hard cut — no sliding animation — which suits a card whose only existing animation is the score-flash.

Three buttons, and what “pause” means

The active section's header becomes a flex row: the title on the left, and on the right a ‹ / toggle / › cluster. The arrows step immediately, wrap, and pause the rotation. The toggle flips between pause and resume — and it is the only control that resumes. Paused, it is drawn orange and shows ▶; running, it shows ⏸. So “I clicked next three times and now it is stuck” is by design: the arrows are for browsing, the toggle is for handing control back to the clock.

The timer is one idempotent method _syncSlideTimer() looks at the world — slide_sec > 0, at least two sections, not paused — and makes the interval match: arm it if it should run and isn't, stop it if it shouldn't and is, otherwise do nothing. It is safe to call on every render, and it is called from _render(), from setConfig, and from every button handler. An earlier draft armed the timer straight from _render() with an if (!this._slideTimer) check; that made a detached-then-reattached card behave differently from the fixed timer (which only ever arms in setConfig). The sync method removed the special case. disconnectedCallback calls _stopSlideTimer() and never the sync, so a stray render after teardown cannot bring the timer back.

Two smaller decisions

Empty sections still take their turn. A section with no games would normally make sectionHtml return nothing; in carousel mode it instead shows its header, its controls, and a “no games” line for the interval. The rotation order stays predictable.

Height holds steady. Sections have different row counts, so a naive carousel jumps height on each advance. When height is not set, the card computes the tallest slide — max over sections of (1 + limit) rows × the row height — and pins that as a min-height. An explicit height still wins. getCardSize(), the masonry hint, switches from the sum of the sections to the largest one.

Reduced motion

A carousel that moves on its own is exactly what prefers-reduced-motion is about. If the viewer's system asks for reduced motion, the card starts paused — the orange ▶ from the first frame, every section still reachable with the arrows, one tap to start it. The check is window.matchMedia?.(…)?.matches === true, optional-chained because jsdom (the test environment) has no matchMedia at all, and an absent one should read as “not reduced”.

The code

Four production files. Built in three slices — carousel + timer, then the controls, then reduced motion.

src/types.ts

slide_sec?: number on CardConfig.

src/index.ts

Fields _slideIndex (number) and _slidePaused (boolean), constructor-initialised and reset in setConfig beside the existing _scoreChangedAt / _prevScores clears — _slidePaused's reset value is _prefersReducedMotion(), not a bare false.

_syncSlideTimer() / _stopSlideTimer() model the existing _fixedTimer pair. _slideStep(dir) wraps the index, sets _slidePaused, syncs, renders; _slideToggle() flips _slidePaused, syncs, renders. _slideBtn(label, glyph, onClick, extra) is a one-line template helper for the three buttons (class, title, aria-label, @click).

_render() calls _syncSlideTimer(), computes carousel, builds the .slide-ctrls cluster when it is on, computes slideMinH when carousel && !height, prepends that to the <ha-card> style string, and maps sections.slice(idx, idx + 1) instead of sections. getCardSize() gains a carousel ? max : sum branch.

src/render.ts

sectionHtml takes two new trailing params, carousel = false and controls = nothing. The header is built once into a local const: plain when there are no controls (byte-identical to before), or .section-header.has-controls wrapping a .section-title span plus the cluster. Both return nothing sites become return carousel ? emptyHtml() : nothing.

src/styles.ts

.section-header.has-controls (flex, space-between); .slide-ctrls; .slide-btn with :hover, :focus-visible, a font-scale-aware size, and .slide-btn.paused { color: orange }.

Guardrail tests

test/index.test.ts › three blocks: “slide_sec carousel” (advance, wrap, index survives a render / resets on setConfig, timer inert after disconnectedCallback, getCardSize, min-height), “slide_sec controls” (button count / order, step + wrap + pause, toggle stops and restarts the timer, paused styling, none in stacked mode), and “slide_sec reduced motion” (stubbed matchMedia: starts paused, no advance, Resume starts it; absent / non-matching matchMedia rotates). A fourth “branch coverage” block closes the defensive paths. test/snapshot.test.ts pins the new CARD_STYLES rules; the snapshot is refreshed. Coverage stays at 100%.

Quiz

A card has `slide_sec: 60` and exactly one section. What renders?

While the carousel is rotating, the user clicks `›` (next) twice. How do they get auto-advance back?

Why is the rotation timer managed by a single `_syncSlideTimer()` called from `_render`, `setConfig` and the handlers, rather than a `_startSlideTimer()` called once?

`window.matchMedia` is read as `window.matchMedia?.("(prefers-reduced-motion: reduce)")?.matches === true`. Why the optional chaining and the explicit `=== true`?

In carousel mode with no `height` set, how does the card avoid changing height as it advances between sections of different lengths?
