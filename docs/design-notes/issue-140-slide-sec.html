slide_sec — rotate the sections as a slideshow

Issue #140 Slug slide-sec Status approved Type feature Slices 3

Problem

A card with several sections renders them stacked, top to bottom, all at once (_render() maps every section through sectionHtml and interpolates the whole array as one child of the <ha-card> template). On a wall display or a small dashboard tile you often want to cycle through them — the NBA board for a minute, then NHL, then back — and watch one at a time.

There is no way to do that, and the card has never needed one: it is display-only. No <button>, no @click, no event binding anywhere in src/; every rendered value is derived from hass. This feature is the card's first interactive control, its first piece of view-state that is not a function of hass (which section is showing, is it paused), and its first rotation timer.

Prior art

LESSONS.md has no entry for timers, carousels, interactivity or view-state — nothing in this problem class has been fixed and guarded. The recon (explorer pass) mapped the machinery this plugs into; the load-bearing facts:

  • Non-hass instance state has an exact precedent. _scoreChangedAt / _prevScores (src/index.ts:24–25) are declared as fields, initialised in the constructor, and explicitly reset in both setConfig and disconnectedCallback (lines 49–50, 149–150), with a dedicated “setConfig cache reset” test. None of them drive a re-render on their own — a _render() call is triggered separately (the blink timer does this). _slideIndex / _slidePaused follow this pattern verbatim.
  • The timer harness has an exact precedent. _fixedTimer is created in _startFixedTimer() (called from setConfig), torn down in _stopFixedTimer(), and cleared in disconnectedCallback. There is no connectedCallback — nothing re-arms a timer on reinsertion except a fresh setConfig. A _slideTimer mirrors this (_startSlideTimer / _stopSlideTimer), and inherits the same “reattach needs setConfig” limitation the fixed timer already has.
  • Timer teardown is a tested contract. test/index.test.ts:476–485 asserts _fixedTimer does not fire after disconnectedCallback(). The slide timer needs the same test. Fake-timer pattern is per-describe: vi.useFakeTimers() / vi.advanceTimersByTime; makeCard() is never appended to the document, so lifecycle callbacks are invoked by hand.
  • .section-header is a plain block (src/render.ts:117): <div class="section-header" style=…>${name}</div>, with the game rows as siblings, not children. Adding controls to its line means making it a flex row.
  • sectionHtml returns nothing for an empty section (src/render.ts:77, :116). The rotation must still show that section's header + controls on its turn, so sectionHtml needs a carousel-aware path (it already owns the header).
  • window.matchMedia is not implemented by jsdom and not stubbed (no setupFiles exists). A raw matchMedia call in src/ throws under test — the reduced-motion check must be optional-chained (window.matchMedia?.(…)?.matches === true), with a per-test stub where the behaviour is exercised.
  • The CSS-custom-property test guardrail applies to any new --scoreboard-* var or px value routed onto <ha-card>: assert on querySelector("ha-card").getAttribute("style"), not innerHTML; a styles.ts edit forces vitest -u on the snapshot, which code-writer cannot do (the driver refreshes it).

Decisions from the grill

Ten decisions, taken one at a time in brainstorm-it; the issue body carries the long form. Condensed:

#Decision
1Option name kept as slide_sec (card-level, seconds). Unset / 0 → today's stacked render, untouched.
2Hard swap between sections — no slide/fade transition. Matches the card's one-animation (score-flash) aesthetic.
3Active when slide_sec > 0 && sections.length >= 2. One section → renders it, no controls, no timer.
4Three <button> controls, all always visible when active: ‹ prev · stop/resume toggle · › next. Unicode glyphs, no ha-icon.
5Toggle glyph: ⏸ while rotating, ▶ while paused. Every button carries title / aria-label.
6‹ / › step immediately, wrapping, and pause rotation if it was running. Only the toggle resumes.
7Paused toggle is painted orange (the card's existing winner accent). Arrows stay muted grey (#888).
8Rotation visits every configured section in order, empty ones included (empty slide = header + controls + “no games” body for the interval).
9Controls sit on the section-header line, right-aligned (title left, cluster right).
10prefers-reduced-motion: reduce → card starts paused (orange ▶ from first render); all sections reachable via the arrows.
State & lifecycle contract _slideIndex (number) and _slidePaused (boolean) are instance fields. They survive every re-render (state_changed, fixed_refresh, blink) and HA reconnects — never recomputed from hass. Reset on setConfig (index 0, playing — unless reduced-motion, then paused). _slideTimer is cleared in disconnectedCallback and re-armed from setConfig. If a config change alters the section count, _slideIndex is taken mod count on the next render. Pausing stops the timer without touching the index.

Height, when height is not set

Sections have different row counts, so a naive carousel jumps height on each advance. Decision: when height is unset and the carousel is active, the card locks to the tallest slide — _render() computes max over sections of (1 + (limit ?? 10)) rows × the row height, and injects min-height through the same haCardStyle string that the height option already uses. An explicit height still wins. getCardSize() switches from sum of section sizes to max in carousel mode, so Home Assistant's masonry reserves the right space.

Design it twice

Chosen

A · Active-section render, logic inline in index.ts

_render() computes carousel; when true it builds sectionTemplates from only sections[_slideIndex] and renders the control cluster into that section's header. sectionHtml gains a carousel path so an empty active section still shows its header + controls. _slideIndex / _slidePaused fields + _slideTimer + _startSlideTimer / _stopSlideTimer, all modelled on _fixedTimer and _scoreChangedAt.

  • Matches how the card already works: _render decides what markup exists from state; sectionHtml already returns nothing/markup conditionally.
  • DOM stays minimal — one section's rows and one section's logo <img>s, not every section's.
  • Every field, timer and teardown has a line-for-line precedent already tested in test/index.test.ts.
  • Keeps a future animated transition cheap — the swap is one clean seam.
  • Cost: .section-header needs a flex modifier in carousel mode (one snapshot line); the tallest-slide height is a small px computation in _render.
Rejected

B · Render every section, toggle visibility with CSS

_render() emits all sections as today, each wrapped in a .slide div; a grid places every slide in the same cell and the inactive ones get visibility: hidden. Advancing could be a class flip without a full _render(). The tallest-slide height falls out of the grid overlap for free.

  • Every section's rows — and every section's logo <img src> — are permanently in the DOM and loaded, even while hidden. Real cost for a multi-league card.
  • The “class flip, no re-render” win evaporates: fixed_refresh and every state_changed re-render within ~60 s anyway, and _render must re-apply the active slide from _slideIndex regardless.
  • Grid-overlap stacking fights the existing height / overflow:hidden option and the absolutely-positioned debug / version overlays.
  • Same instance state, @click and timer as A on the JS side — it moves complexity into fussier CSS and adds hidden-DOM weight, for one free height lock.

A third shape — extract a SlideController helper class (like SubscriptionManager / DebugMetrics from ha-card-shared) holding index / paused / timer — was considered. It tests in isolation and mirrors the composition style of those helpers, but this repo keeps all card logic in the top-level modules with no local helper classes, and two fields + one timer + four one-line methods do not clear the bar for a new file and a new pattern. If the inline version bloats index.ts during /code-it, revisit then.

The change — three slices

Slice 1 — the carousel, no controls

  • src/types.ts — slide_sec?: number on CardConfig.
  • src/index.ts — _slideIndex / _slidePaused fields (constructor init; reset in setConfig + disconnectedCallback). _startSlideTimer / _stopSlideTimer (interval = slide_sec * 1000; callback bumps _slideIndex mod count and calls _render); wired into setConfig and disconnectedCallback beside the fixed timer. _render(): when slide_sec > 0 && sections.length >= 2, render only sections[_slideIndex mod n]; else unchanged. Tallest-slide min-height into haCardStyle when height unset. getCardSize(): max not sum in carousel mode.
  • src/render.ts — sectionHtml carousel path: render the header + “no games” body instead of nothing when told this is the active slide.
  • test/index.test.ts — carousel on/off threshold; advance + wrap on the timer; index survives a re-render, resets on setConfig; timer cleared on disconnect and does not fire after; getCardSize max-vs-sum; tallest-slide min-height on the ha-card style attribute.

Slice 2 — the three controls

  • src/render.ts (or a small widgets.ts helper) — the ‹ ⏸/▶ › cluster as a TemplateResult, @click bound to callbacks passed in from _render; title / aria-label on each. .section-header becomes a flex row in carousel mode (modifier class).
  • src/index.ts — _slidePrev / _slideNext (step + wrap + set _slidePaused = true + _stopSlideTimer); _slideToggle (flip _slidePaused; start or stop the timer). Pass the three handlers into the section template.
  • src/styles.ts — .slide-btn (muted grey chrome, focus ring, hit target); paused toggle painted orange; header flex modifier.
  • test/index.test.ts — click prev/next steps + wraps + pauses; toggle pauses then resumes and (re)arms the timer; glyph + orange class reflect _slidePaused; buttons absent when not in carousel mode. test/snapshot.test.ts — CARD_STYLES gains the button rules; snapshot refreshed.

Slice 3 — honour prefers-reduced-motion

  • src/index.ts — on the initial carousel setup, if window.matchMedia?.("(prefers-reduced-motion: reduce)")?.matches === true, start with _slidePaused = true and do not arm the timer. Optional-chained so a missing matchMedia is simply “not reduced”.
  • test/index.test.ts — stub window.matchMedia per test: reduced → first render paused, orange ▶, no timer; not-reduced / matchMedia absent → rotates normally.

README.md gets a slide_sec row + a “Rotating sections” section (controls, pause colour, reduced-motion, the height interaction) as part of the slice that first makes each behaviour real. Coverage stays at 100% throughout.

Design invariant touched

New invariant for CLAUDE.md — Design Invariants: “With slide_sec set and ≥ 2 sections the card shows one section at a time and auto-advances every slide_sec seconds; ‹/› step and pause, the stop toggle (orange while paused) is the only resume, and prefers-reduced-motion starts it paused. Unset / 0 / a single section ⇒ today's stacked render, unchanged.” Plus an Architecture Notes line: the card now carries view-state (_slideIndex / _slidePaused) and a @click interaction pattern — state reset mirrors _scoreChangedAt, timer teardown mirrors _fixedTimer.

Adjacent opportunities

  • Animated slide / crossfade transition — approach A leaves the swap as one seam a CSS transition wrapper slots into. Already named out-of-scope in #140; own issue if the hard cut feels abrupt in practice.
  • Per-section dwell time — slide_sec as a SectionConfig field so a busy league lingers longer. Genuinely separate; file only if asked.
  • Progress affordance — a countdown bar or dots pager driven by the same interval. Out-of-scope in #140; separate issue.
  • Configurable pause colour via the existing colors map. Trivial once the control exists; deferred, not folded in.

This change forecloses nothing structural and gives the card its first reusable interaction pattern for whatever interactive bit comes next.

Slice log

Slice 1 — the carousel, no controls  ·  accepted

  • src/types.ts — slide_sec?: number on CardConfig.
  • src/index.ts — _slideTimer / _slideIndex fields (constructor-inited; _slideIndex reset + _startSlideTimer() in setConfig; _stopSlideTimer() in disconnectedCallback — mirroring _fixedTimer / _scoreChangedAt). _startSlideTimer arms an interval only when slide_sec > 0 && sections.length >= 2; the callback bumps _slideIndex mod n and re-renders. _render() destructures slide_sec, computes carousel, renders sections.slice(idx, idx+1) when carousel (else all sections), and prepends min-height:<maxRows×rowH>px into haCardStyle when carousel && !height. getCardSize() uses max over sections in carousel mode, the existing sum otherwise.
  • src/render.ts — sectionHtml gains carousel = false; the two return nothing sites become carousel ? emptyHtml() : nothing (header + “no games”), the non-carousel path byte-unchanged. Shared .section-header template factored to a local const.
  • test/index.test.ts — describe("slide_sec carousel"), 14 cases: on/off threshold, single-section no-op, advance + wrap on the timer, _slideIndex survives a re-render / resets on setConfig, timer cleared on disconnect and inert after, getCardSize max<sum, tallest-slide min-height on the ha-card style attribute + explicit height wins.

Suite 312 green; typecheck / check:ci clean; coverage 100%. Reviewer: no correctness findings; /simplify removed a dead overflow:hidden from slideMinH (nothing to clip — the active slide never exceeds the computed min-height), scoped the maxRows computation behind carousel && !height, and factored the duplicated header template.

Carried into slice 2 _startSlideTimer() is currently also armed lazily from _render() (if (!this._slideTimer)) because the frozen slice-1 tests assign _config directly without setConfig. Consequence: on detach→reattach the slide timer resumes via set hass's first _render() while _fixedTimer (armed only in setConfig) stays down — a mild divergence, not a fault (the interval callback is guarded by this._hass && this._config). Slice 2 folds arm / pause / resume into a single _syncSlideTimer() gated on _slidePaused, which is the natural place to make the lifecycle consistent.
