Design note · ha-teamtracker-scoreboard-card

Card-level show_position to drop the position gutter

Issue #134 Slug card-level-position-toggle Status approved Type feature Slices 1

Problem

#132 draws an 18px .team-pos cell as the first child of every .game-row — numbered in a ranking sort, blank under by-date or when a section sets show_position: false. The cell is always present so that a card mixing a standings section and a fixture section keeps its rows left-aligned, with no card-wide pre-pass.

The cost lands on a card that has only fixture / by-date sections: it gains a permanent empty 18px gutter it never had before #132, for an alignment guarantee it doesn't need. There is no way to opt the whole card out.

Prior art

LESSONS.md has no entry for this problem class — no gutter / alignment / position-column fix has been made and guarded. The relevant context is the #132 design invariant in CLAUDE.md (“every row opens with a fixed-width position cell… drawn but empty… so mixed cards stay row-aligned”) and the LESSONS.md rule from #132/#133 that --scoreboard-* options are tested on the <ha-card> style attribute, not innerHTML — which this change follows.

Decision from the grill

Name & precedence Card-level show_position (boolean) — the same key as the section option. Card show_position: false wins hard: no .team-pos cell on any row, section settings ignored. Card unset or true ⇒ today's behaviour exactly, and the section-level show_position (default true) decides the number per section.
  • The two levels are deliberately not identical: the section option blanks the number but keeps the cell (for alignment); the card option removes the cell (for pre-#132 layout). One is a content switch, the other structural. The README says so plainly.
  • Only show_position: false at card level does anything; true and omitted are the same no-op, so setting it defensively can't regress a card.

Behaviour table

Card show_positionSection show_positionResult
omitted / truetrue (default), ranking sortnumbered 18px cell — unchanged
omitted / truefalse, or by-dateblank 18px cell — unchanged
falseanythingno cell — exact pre-#132 layout

Design it twice

Chosen

A · CSS custom property, no render.ts change

_render() adds one cssVars entry — "--scoreboard-position-display": show_position === false ? "none" : undefined — so the property lands on <ha-card> only when the card explicitly opts out. .team-pos gains display: var(--scoreboard-position-display, block). 

.team-pos {
  display: var(--scoreboard-position-display, block);
  width: 18px; min-width: 18px;
  /* … unchanged … */
}
  • display: none takes the cell out of the flex flow entirely — the 18px is gone, not just hidden. Exact pre-#132 row.
  • Zero change to rowHtml / sectionHtml; no new param threaded through two layers; rowHtml's test surface untouched.
  • One cssVars line + one CSS line + one type field. Slots into the exact pattern #132/#133 established.
  • Trade-off: the <div class="team-pos"> is still in the DOM (empty, display:none). Invisible and zero-area — acceptable.
Rejected

B · Thread a boolean into rowHtml

_render passes the card flag to sectionHtml, which passes positionColumn = false to rowHtml, which omits the <div class="team-pos"> node.

  • The node is truly absent from the DOM — marginally cleaner markup.
  • But sectionHtml has no card-level argument today; this adds a 6th positional param (after colors, scoreChangedAt) or forces an options-object refactor.
  • rowHtml gains a 7th param and every structural snapshot plus the "first child is .team-pos" test needs a variant.
  • All to avoid one inert hidden <div>. Not worth it.

The change — one slice

  • src/types.ts — show_position?: boolean on CardConfig (the field already exists on SectionConfig).
  • src/index.ts — destructure card-level show_position in _render(); add "--scoreboard-position-display": show_position === false ? "none" : undefined to the cssVars table. The existing .filter(([, v]) => v) keeps it out of the style string in every other case.
  • src/styles.ts — .team-pos gains display: var(--scoreboard-position-display, block) as its first declaration.
  • test/index.test.ts — card show_position: false ⇒ --scoreboard-position-display:none on the <ha-card> style attribute; omitted and true ⇒ absent.
  • test/snapshot.test.ts — CARD_STYLES contains display: var(--scoreboard-position-display, block); snapshot refreshed.
  • README.md — card-level show_position row in Options; a paragraph in "Standings position" distinguishing card (removes the column) from section (blanks the number).
  • CLAUDE.md — the #132 invariant bullet gains a trailing clause: card show_position: false removes the gutter entirely.

No getCardSize() change — the gutter is horizontal only. Coverage stays at 100%.

Design invariant touched

“Every row opens with a fixed-width position cell (.team-pos)… the cell is drawn but empty, so mixed standings/fixture cards stay row-aligned without a card-wide pre-pass.”

Still the default. The invariant text gains: “unless the card sets show_position: false, which drops the cell for the whole card.” The alignment guarantee only ever mattered for cards that mix section types; a card opting out has decided it doesn't.

Adjacent opportunities

  • position_width — a card knob to resize (rather than remove) the gutter, on the same --scoreboard-* mechanism. Deferred from the #133 note; #134 covers the "remove" case, not the "resize" case. File separately only if asked.
  • Section-level cell removal — a section that both opts out and collapses its gutter, breaking alignment with its siblings on purpose. Coherent but niche; not pursued.
  • Config validation for boolean / enum options — still absent card-wide, still out of scope.

This change makes position_width trivial (same property family) and forecloses nothing.

Slice log

Slice 1 — accepted. The whole change, CSS-only, as designed.

  • src/types.ts — show_position?: boolean on CardConfig with a one-line intent comment (the field name is shared with SectionConfig; the interfaces are independent so there is no type conflict, and _render / sectionHtml read it from different objects).

  • src/styles.ts — .team-pos gains display: var(--scoreboard-position-display, block) as its first declaration. display:none removes the flex child from the row's formatting context, so the 18px is reclaimed, not merely hidden.
  • test/index.test.ts — describe("card-level show_position"): false emits --scoreboard-position-display:none on the <ha-card> style attribute; omitted and true emit nothing.

  • CLAUDE.md — the position-cell invariant gains the card-level show_position: false caveat.
