Section override for season_mode sort detection

Issue #130 Slug season-mode-override Status approved Type feature Slices 1

Problem

resolveSortMode (src/sorting.ts) picks the sort automatically from the tracked sensors' season attribute: if any sensor reports a season that is truthy and !== "regular", the card switches to the by-date fixture table; otherwise it ranks by the section's rank_type.

Some leagues never emit a clean season-type token. TeamTracker's Italian Serie A sensors (ita.1) report season: 2026-27-italian-serie-a — a descriptive label, not regular / pre / post / off. The heuristic reads that as "not regular" and flips Serie A to the fixture table during the regular season, with no way to correct it from config. The reverse also happens: a user may want the fixture table for a league the heuristic leaves in standings mode.

Prior art

No LESSONS.md entry for this problem class — the file does not exist yet; this is the first design note in the repo. The existing behaviour is covered by the design invariant in CLAUDE.md ("Sort switches to by-date automatically during non-regular season … undefined season counts as regular") and by four resolveSortMode tests in test/sorting.test.ts. Nothing here has been fixed-and-guarded before; this is a new capability on top of the invariant, not a regression.

Decision from the grill

Naming Keep the option and value vocabulary exactly as the issue proposes: season_mode: auto | regular | by-date, default auto. regular mirrors the sensor's own season vocabulary; by-date is already the SortMode value and matches the README's "sorts rows by game date" wording. Alternatives considered (standings_mode: auto | standings | fixtures, season_mode: auto | regular | fixtures) were set aside to avoid introducing a third name for concepts the codebase already names.

Design it twice

Chosen

A · Explicit season_mode override

New SeasonMode type and season_mode? on SectionConfig. resolveSortMode takes a 4th param and short-circuits before the heuristic. render.ts reads season_mode from the section and passes it through.

  • Handles both directions — force standings, or force fixtures.
  • Default auto ⇒ zero behaviour change on upgrade.
  • Visible in YAML when debugging a wrong sort.
  • ~15 LOC + README + tests.
Rejected

B · Smarter auto, no new option

Change the heuristic from "season truthy and !== "regular"" to "season matches a known non-regular token set (pre, post, off, playoff(s)…)". Serie A's label matches nothing ⇒ treated as regular, fixed with no config.

  • Can't express the issue's reverse case (want fixtures where heuristic says standings).
  • Maintained token list — every novel season label is a fresh bug; a cup reporting a bare descriptive label during knockout rounds silently regresses to standings.
  • Silently changes behaviour for every existing user on upgrade.

B's merit — the common case needs no config — is real, but it belongs as a separate refinement to the auto branch, complementary to the override rather than a substitute for it. Filed as an adjacent opportunity below.

The change

Behaviour table

ValueEffect
autoCurrent behaviour — fixture table when any sensor's season is set and not regular. Default.
regularAlways rank by rank_type, whatever season says.
by-dateAlways the date-sorted fixture table, one row per game.

Config

sections:
  - name: Serie A
    prefix: sensor.sera_
    rank_type: win-draw-loss
    season_mode: regular   # treat as regular season even though the sensor doesn't say so

Short-circuit in resolveSortMode

export function resolveSortMode(
  entities: string[],
  states: HassStates,
  rankType: SortMode,
  seasonMode: SeasonMode = "auto",
): SortMode {
  if (seasonMode === "by-date") return "by-date";
  if (seasonMode === "regular") return rankType;
  return entities.some((id) => {
    const s = states[id]?.attributes?.season;
    return s && s !== "regular";
  })
    ? "by-date"
    : rankType;
}

An unrecognised season_mode value falls through to the auto branch. This matches how rank_type is handled today — no config validation layer exists, and adding one is out of scope (see adjacent opportunities).

Design invariant touched

"Sort switches to by-date automatically during non-regular season (playoffs, off-season); undefined season counts as regular."

Still the default — season_mode: auto preserves it verbatim. This note adds an explicit per-section override on top. The invariant text in CLAUDE.md gets a trailing clause noting the override exists.

Adjacent opportunities

  • Smarter auto token recognition (Approach B as a refinement) — recognise descriptive season labels that contain no season-type token as regular. Slots in behind the auto branch with no signature change once this lands. New GH issue, not folded in here.
  • Config validation for enum section options — rank_type is already unvalidated; a shared validator for rank_type + season_mode is a pre-existing gap, out of scope for this change.

This change makes the first item cheap and forecloses nothing.
