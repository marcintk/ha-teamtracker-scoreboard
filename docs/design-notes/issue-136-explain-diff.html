Background

The card draws every game as a single flex row: a position cell, two team columns, two score cells with a colon between them, two logos, and a message column. Earlier work made the row's dimensions configurable — row_height, logo_width, score_width, colon_width, team_width. Each of those options works the same way: _render() builds a small cssVars table, its entries are serialised into the style attribute of the <ha-card> element as --scoreboard-* custom properties, and the stylesheet reads each one with a var(--name, fallback) so a card that sets nothing renders exactly as before.

What stayed fixed was the type. Every font-size in src/styles.ts was a hard-coded pixel literal: the score at 20px, the section header at 15px, the team name at 13px, the rank at 9px, the TV badge at 8px, and so on down a list of twelve rules. A viewer who found the card a touch small on a wall-mounted tablet, or too large on a dense dashboard, had no way to say so. That is a readability need, and it is a different need from “make the row fit” — the dimension knobs already cover the latter.

This change adds one card-level option, font_scale, a single number that multiplies the whole type set by one factor.

The idea

The twelve pixel literals were not chosen independently — they are a scale, tuned as a set. The score is about 1.5× the team name; the rank is about 0.7× it. If you want the card bigger, you almost always want that whole relationship to grow together, not to re-pick twelve numbers by hand. So the option is a multiplier, not a bag of per-role sizes.

The mechanism is the smallest thing that could work. Each rule keeps its literal as a baseline and multiplies by a CSS variable that defaults to 1:

.score { font-size: calc(20px * var(--scoreboard-font-scale, 1)); }

With the variable unset, calc(20px * 1) is 20px — the rule is byte-for-byte what it was. Set font_scale: 1.15 and _render() puts --scoreboard-font-scale: 1.15 on the <ha-card>; now the same rule computes 23px, the header computes 17.25px, the rank 10.35px, and the browser does all the arithmetic. There is no JavaScript math and no unit handling — a bare number is a valid operand on either side of * in calc().

Why the emit guard is != null && !== 1 The cssVars table is serialised through .filter(([, v]) => v) — only truthy values become declarations. A plain truthy check (font_scale ? …) would do almost the right thing, but it would also swallow font_scale: 0. The explicit form emits when the value is set and is not the 1 baseline, so: omitted → nothing; 1 → nothing (a deliberate no-op); 0 → --scoreboard-font-scale:0 reaches the stylesheet and every rule collapses to 0px. That last case is nonsense input, but it is honest nonsense — calc(20px * 0) is valid CSS, nothing crashes, and it does exactly what was asked. No value is range-checked, which is consistent with the width knobs next to it.

What does not move

font_scale is typography only. It does not touch row_height, the column widths, or the logo size, and it does not feed getCardSize(). So a large font_scale puts bigger text into an unchanged row: at 1.5 the 30px score sits in a 28px row and clips top and bottom. The fix is to raise row_height alongside it — the knobs stay independent by design, and the README says so.

The one rule left alone

.tv { font-size: 0 } keeps its literal. That zero is not a type size — it is the old trick for collapsing whitespace between inline children of the TV-badge container. Its visible child, .tv-badge, re-sets a real, scaled size. Wrapping the zero would have been harmless (calc(0px * s) is still 0) but it would have muddied what the line is for.

The code

Five added lines across three files; src/render.ts and getCardSize() are untouched.

src/types.ts

font_scale?: number on CardConfig, with a one-line intent comment. Card-level, like the dimension knobs; not a section option.

src/index.ts

_render() destructures font_scale and adds one entry to the cssVars table:

"--scoreboard-font-scale":
  font_scale != null && font_scale !== 1 ? String(font_scale) : undefined,

The existing .filter(([, v]) => v).map(…).join("") turns it into a --scoreboard-font-scale:1.15; fragment on the <ha-card> style, or drops it when the value is undefined.

src/styles.ts

The twelve text font-size: Npx declarations in CARD_STYLES become font-size: calc(Npx * var(--scoreboard-font-scale, 1)) — ha-card base, .section-header, .team-pos, .team-name, .team-rank, .score, .colon, .tv-badge, .tv-tooltip::after, .message, .msg-sub, .empty. .tv { font-size: 0 } is deliberately not wrapped.

Guardrail tests

Coverage stays at 100%.
