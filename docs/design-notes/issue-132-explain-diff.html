Background

The card renders one .game-row per game as a flat CSS flexbox: a team-name column, a logo, a score, a colon, a mirrored score/logo/name for the opponent, then a free-text message column. Rows are grouped into sections, one per league, each driven by a config block with a prefix that selects the sensors to show.

A section renders in one of two worlds. During the regular season, resolveSortMode returns a ranking mode (win-loss, win-draw-loss, win-loss-otl) and sectionHtml sorts the teams by win ratio, best first — the row order is the league table. Outside the regular season it returns by-date and the same rows become a chronological fixture list. A section option, season_mode, can force either world when the sensor's season label is ambiguous.

Two gaps motivated this change. First, in the ranking world the standing was implied by row order and nowhere written down; you counted rows to find out that a team sat 4th. Second, the two team-name columns were pinned at width: 99px with a min-width: 60px floor, hard-coded in the stylesheet with no way to widen them for long club names or narrow them for a tight dashboard.

This change adds a card-level team_col_width option and a per-row position number in a new left-most cell, with a section-level show_position switch to turn the number off.

The idea

The width knob is a CSS variable with a fallback

Nothing about the layout math changes. _render writes one extra declaration onto the <ha-card> element's inline style when the option is set:

height ? "height:...;" : ""
+ (debug || show_version ? "position:relative;" : "")
+ (team_col_width ? `--scoreboard-team-col-width:${team_col_width};` : "")

and the stylesheet reads it with a fallback:

.team-col { width: var(--scoreboard-team-col-width, 99px);
           min-width: var(--scoreboard-team-col-width, 99px); }

If the option is absent, the custom property is never defined, the fallback 99px applies, and the card is byte-for-byte what it was before. If it is set, both width and min-width take the new value — the old 60px floor is deliberately gone so the number you type is the number you get.

The position is an array index that already exists

sectionHtml has already sorted the teams before it renders anything. The position of a team in the standings is just its index in that sorted array, plus one. So we tag each item with it, right after the sort and before the limit slice:

items.sort(...);
const ranked = items.map((it, i) => ({ ...it, position: i + 1 }));
const rows = deduplicate(ranked, sortMode, states).slice(0, limit).map(...)

Tagging before the slice matters: a section showing limit: 5 of a 20-team league still labels its top row 1, because the number describes the standing, not the position on screen.

Why the cell is drawn even when it's empty Sections render independently — there is no card-wide pass that could reserve space. If the position cell only appeared in ranking mode, a card stacking a league table above a playoffs bracket would have its rows start at two different left edges. So rowHtml always emits an 18 px <div class="team-pos"> as the first child of the row: the digit in ranking mode, nothing under by-date or when show_position: false. Every row lines up regardless.

The number is coloured like its team. The sensor's own team sits on side A when team_homeaway === "home" and side B otherwise, and rowHtml has already computed homeColor and awayColor, so the position colour is just team_homeaway === "home" ? homeColor : awayColor — no new colour logic.

The code

Four production files, ~42 lines.

src/types.ts

Three optional fields: team_col_width?: string on CardConfig, show_position?: boolean on SectionConfig, and position?: number on the internal SortItem.

src/index.ts

_render pulls team_col_width out of the config and appends --scoreboard-team-col-width:<value>; to the haCardStyle string when it is set — the same conditional-fragment pattern already used for height and the debug overlay's position:relative.

src/styles.ts

A new .team-pos rule — 18px fixed width, font-variant-numeric: tabular-nums, centred — placed just before .team-col. And .team-col's width / min-width become var(--scoreboard-team-col-width, 99px), dropping the separate 60px minimum.

src/render.ts

rowHtml takes a new trailing parameter position: number | null = null, computes posColor from the existing home/away colours, and renders <div class="team-pos" style=${position == null ? nothing : `color:${posColor}`}>${position ?? ""}</div> as the first child of .game-row. sectionHtml destructures show_position = true, builds the ranked array with a position on every item before dedup and slice, and passes sortMode !== "by-date" && show_position ? position : null down to each rowHtml call.

Guardrail tests

test/render.test.ts › "standings position column" (7 cases: numbers in sorted order, first-child placement, show_position: false and by-date both leaving the cell present but empty, special-team colouring, and rowHtml with and without the argument). test/index.test.ts › "team_col_width" asserts the custom property lands on the <ha-card> style attribute only when configured; test/snapshot.test.ts pins the CARD_STYLES wiring. The rowHtml structural snapshots and the CARD_STYLES snapshot were regenerated to include the empty .team-pos cell and the new rule. Coverage stays at 100%.
