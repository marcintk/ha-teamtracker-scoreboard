Standings position column & configurable team-column width

Issue #132 Slug standings-position-column Status approved Type feature Slices 2

Problem

In the regular season, sectionHtml (src/render.ts) ranks every tracked team by win ratio and lays the rows out top–to–bottom — but the row never states the team's position. The reader infers it by counting rows. There is no number on screen and no way to add one.

Separately, the two team-name columns are locked at width: 99px in src/styles.ts (.team-col), with a min-width: 60px floor. Long club names ellipsise; narrow dashboards waste the space. Nothing in the config reaches this number.

Prior art

LESSONS.md has one entry — the resolveSortMode heuristic fix from #130. Different problem class (which sort runs), but the same switch is the hinge here: the position column shows only when resolveSortMode returns a ranking mode, i.e. not by-date. That decision point already exists and is already covered by the seasonMode tests in test/sorting.test.ts; this change reads its output, it does not touch it. No layout, column, or CSS-variable concern has been fixed-and-guarded before — there is nothing here that a guardrail already prevents.

Decision from the grill

Naming & shape show_position — section option, boolean, default true. Opts a section out of the numbers (the gutter stays, for alignment).
team_col_width — card option, CSS length string, default 99px. One value for both columns; the current design centres the score between two symmetric columns, so separate A/B widths are deliberately out of scope (own issue).
The position column itself has no option — fixed 18px, "as narrow as possible", two digits, plain integer, no ordinal suffix.
  • Where the number comes from: the row's 1-based index in the sorted, pre-limit item list. Not the team_rank attribute (TeamTracker standings sensors don't populate a league position; it would read blank). Because the index is taken before the limit slice, #1 is the true section leader even when lower rows are cut off.
  • Whose position: the row's tracked team — the sensor's own team, which renders on side A or side B depending on team_homeaway. The number sits in a single leftmost cell and is coloured like that team (so a special_teams entry's position highlights too).
  • by-date mode: the leftmost cell is still rendered, same 18px, empty. A card mixing a standings section and a fixture section keeps its rows aligned. The gutter is always reserved — no card-wide pre-pass, sections stay independent (per the architecture note in CLAUDE.md).

Design it twice

Axis 1 — how the number reaches the row

Chosen

A · Compute in sectionHtml, pass a rowHtml arg

After the existing items.sort(...), map each item to { ...it, position: i + 1 } before deduplicate / slice. rowHtml gains a trailing position: number | null and always renders a .team-pos cell — the number, or empty when null.

  • Index is the standings position — free, exact, pre-limit.
  • One trailing optional arg, matching the existing opponentSpecial / isFresh pattern; every current rowHtml call still compiles.
  • by-date, show_position: false and "reserve the gutter" all converge on one path: position === null ⇒ empty cell.
  • Sections stay independent — no card-level coordination.
  • ~20 LOC across two files + CSS.
Rejected

B · Enrich SortItem, widen rowHtml to take the item

Add position to SortItem, set it after the sort, let deduplicate carry it through. Change rowHtml(stateObj, special, colors, opponentSpecial, isFresh) to take the SortItem and read special / opponentSpecial / position off it.

  • Consolidates three item-derived args into one object — a real cleanup…
  • …but rewrites every rowHtml call site and most row-construction in test/render.test.ts and test/styles.test.ts, which build ad-hoc partial items today.
  • Large, risky diff for a cosmetic gain, disproportionate to the feature.

B's arg-consolidation merit is genuine but belongs in its own refactor, not riding this feature. Approach A keeps the blast radius at "one new cell, one new arg".

Axis 2 — how team_col_width reaches the CSS

Chosen

A · CSS custom property on <ha-card>

Append --scoreboard-team-col-width: <value> to the existing haCardStyle string in _render (src/index.ts); .team-col reads width: var(--scoreboard-team-col-width, 99px). Matches the existing var(--scoreboard-*) convention already used for colours.

  • One declaration site; CSS stays static and testable.
  • Card-level value never has to thread through the section layer.
Rejected

B · Inline style="width:…" per column

Pass the width down into rowHtml and stamp it inline on .team-col-a / .team-col-b.

  • Repeats the value twice per row, bloats the row template.
  • Threads a card-level constant through sectionHtml → rowHtml for no benefit.

Slices

Slice 1 — team_col_width card option

Isolated: de-risks the CSS-custom-property plumbing before the row template is touched. No interaction with sort or sections.

  • src/types.ts — team_col_width?: string on CardConfig.
  • src/index.ts — destructure it in _render; append --scoreboard-team-col-width to haCardStyle.
  • src/styles.ts — .team-col width + min-width → var(--scoreboard-team-col-width, 99px); drop the 60px floor.
  • test/index.test.ts — option present ⇒ custom property in the card style; absent ⇒ style string unchanged.
  • test/__snapshots__/ — style-block snapshot refreshed.
  • README.md — row in the Options table.

Slice 2 — standings position column

  • src/types.ts — position?: number on SortItem; show_position?: boolean on SectionConfig.
  • src/render.ts — sectionHtml ranks pre-limit, reads show_position = true, passes position (or null for by-date / opt-out); rowHtml gains the trailing param and the .team-pos first child, coloured via the existing teamColor on the tracked side.
  • src/styles.ts — .team-pos rule.
  • test/render.test.ts — numbers run 1..N by standings order; #1 is the leader even past limit; show_position: false ⇒ cell present, empty; by-date ⇒ cell present, empty; a special_teams row's number carries the special colour.
  • test/__snapshots__/ — row + style snapshots refreshed.
  • README.md — show_position row in Section options; new "Standings position" subsection after "Rank type".
  • CLAUDE.md — Architecture note: the always-reserved 18px position gutter; number = pre-limit rank of the row's tracked team; blank under by-date.

Coverage stays at 100%. Order: Slice 1 then Slice 2.

Design invariants touched

None of the three CLAUDE.md design invariants change. by-date still shows one entry per game; the position column is simply blank there. A new layout fact is added to the Architecture Notes: every row now opens with an 18px cell, numbered only in ranking mode with show_position on, so mixed standings/fixture cards stay aligned without any cross-section pass.

Adjacent opportunities

  • Expose the remaining row dimensions (logo / score / colon / row-height) as a dimensions: map on the same custom-property mechanism — filed as #133. This change lays the first stone; separate A/B column widths fold in there too.
  • Card-level master switch to drop the gutter entirely — restore the exact pre-#132 layout for pure-fixture cards — filed as #134. Only worth doing if the always-on gutter is reported as a regression.
  • Config validation for enum / length options — still no validator for rank_type or season_mode; show_position and team_col_width join the same pre-existing gap. Out of scope, same call as #130.

This change makes #133 cheap and forecloses nothing.
